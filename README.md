# 매일 아침 마켓 브리핑 (텔레그램 자동 발송)

매 영업일 아침, 시장지표 본문과 2개년 차트 10장을 텔레그램으로 보낸다.
GitHub Actions에서 실행되므로 **PC를 켜둘 필요가 없다.**

> 사내망에서는 `api.telegram.org` 가 차단되어 있다(TCP는 열리나 TLS 핸드셰이크 타임아웃).
> 그래서 발송 주체를 사내 PC가 아니라 GitHub Actions로 둔다.

## 보내는 내용

**본문**

```
□ 미국증시: Dow (+0.51%), S&P500 (+0.02%), Nasdaq (-0.18%)
□ 섹터별 등락: 필수소비재 +1.46% / … / 에너지 -2.11%   (11개 섹터)
□ 미국국채: 2yr 4.316%(-0.7bp), 10yr 4.635%(-0.6bp), 30yr 5.125%(+0.0bp)

□ 회사 AA- 3년 4.57%(-8bp)
□ 회사 AA- 3년 Spread 71.0bp(+1bp)
```

**차트 22장** — 텔레그램 앨범 상한(10장)에 맞춰 3개 앨범으로 나뉘어 간다.

| 앨범 | 장수 | 내용 |
|---|---|---|
| 1 | 10 | Dow · S&P500 · Nasdaq · 미국채 2/10/30년 · 원달러 · 회사채 AA- 3년 · AA- 스프레드 · 섹터 일간 등락 막대 |
| 2~3 | 12 | 섹터 11종 2개년 상대성과(2년 전 = 100) + 섹터별 개별 2개년 추이 11장 |

개별 추이 차트는 모두 **2개년 + 20/60/120일 이동평균**이다.
섹터 개별 차트는 당일 등락률 높은 순으로 나열된다.

### 종목 등락 메모에 대하여

섹터 차트 캡션에는 비중 상위 5종목의 당일 등락이 붙고, 그중 **±3% 이상 움직인 종목**에
한해 관련 뉴스 헤드라인을 근거로 한 줄 메모가 붙는다.

이건 **"등락 이유"가 아니다.** 주가가 왜 움직였는지는 사후 해석이고, 헤드라인이 곧
원인도 아니다. 그래서 다음을 강제한다.

- 수집한 헤드라인에만 근거하고, 없는 사실·수치는 만들지 않는다
- 헤드라인이 등락을 설명하지 못하면 **메모를 비워 둔다** (억지로 채우지 않는 게 정답)
- "~때문에 급락"이 아니라 "~보도"처럼 인과를 단정하지 않는다
- 캡션에 "등락 원인 단정 아님"을 항상 함께 표시한다

실제로 야후 뉴스 검색은 노이즈가 많다(AAPL 검색에 SK하이닉스 기사가 섞여 나온다).
메모가 비어 있는 건 고장이 아니라 의도된 동작이다.

모델은 `claude-opus-5`, effort `medium`, 하루 1회 호출. 수집·요약 어느 단계가 실패해도
발송 자체는 막지 않는다.

### 알려진 한계

- **국내 금리 정밀도**: 네이버는 소수 **2자리**까지만 공시한다. 따라서 bp 변동이
  `-8.2bp` 가 아니라 `-8bp` 로, 스프레드는 ±1bp 오차가 생긴다.
  소수 3자리가 필요하면 KOFIA(채권정보센터) 연동이 필요하다.
- **여전채 미포함**: 카드 AA+ 3년, 캐피탈 AA- / A+ 3년은 무료 공개 소스가 없어 제외했다.
  (KOFIA XML 서비스는 살아 있으나 서비스명을 아직 찾지 못했다.)
- **한국 CDS 미포함**: 무료 소스가 없다. investing.com 은 403, worldgovernmentbonds 는
  값이 JS로 렌더되어 서버 응답이 비어 있다.
- **원/달러 기준**: Yahoo 글로벌 스팟이라 '서울 외환시장 종가'와는 정의가 다르다.
  아침 브리핑 관점에서는 간밤 뉴욕장까지 반영된 값이라 오히려 최신이다.

## 최초 설정 (한 번만)

### 1. 텔레그램 봇 만들기

사내망에서는 텔레그램이 막혀 있으니 **휴대폰(LTE/5G)** 에서 진행한다.

1. 텔레그램에서 `@BotFather` 검색 → `/newbot` → 이름 정하기
2. 발급된 **토큰**을 복사해 둔다 (`1234567890:AAE...` 형태)
3. 방금 만든 내 봇과의 대화방을 열고 아무 메시지나 하나 보낸다
4. **chat_id 확인**: 브라우저에서 아래 주소를 연다
   `https://api.telegram.org/bot<토큰>/getUpdates`
   응답의 `"chat":{"id":123456789}` 에서 그 숫자가 chat_id 다.

> 토큰은 비밀번호와 같다. 코드나 채팅에 붙여넣지 말고 아래 3번의 GitHub Secrets 에만 넣는다.

### 2. GitHub 저장소에 올리기

github.com 에서 **Private** 저장소를 하나 만든 뒤(README 체크는 해제), 이 폴더에서:

```bash
git remote add origin https://github.com/<본인계정>/<저장소이름>.git
git push -u origin main
```

### 3. GitHub Secrets 등록

저장소 → **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 값 | 필수 |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | 1번에서 받은 봇 토큰 | ✅ |
| `TELEGRAM_CHAT_ID` | 1번에서 확인한 chat_id | ✅ |
| `CLAUDE_CODE_OAUTH_TOKEN` | 뉴스 요약용 — **구독으로 쓰는 방법** | 선택 |
| `ANTHROPIC_API_KEY` | 뉴스 요약용 — API 크레딧 방식 | 선택 |

### 뉴스 요약 인증: 구독 vs API 키

**구독(Pro/Max)을 쓰면 추가 비용이 없다.** 로컬에서 아래를 실행해 장기 토큰을 발급받고,
그 값을 `CLAUDE_CODE_OAUTH_TOKEN` 시크릿에 넣는다.

```bash
claude setup-token
```

이러면 GitHub Actions가 Claude Code 헤드리스 모드로 요약을 돌리고, 사용량은 구독
한도에서 차감된다. API 크레딧을 따로 충전할 필요가 없다.

`ANTHROPIC_API_KEY` 는 구독을 쓰지 않을 때의 대안이다. 사용량만큼 별도 과금된다.

둘 다 넣으면 **구독 토큰을 먼저** 쓴다. 둘 다 없으면 요약만 빠지고 나머지는 그대로
발송된다.

### 4. 동작 확인

저장소 → **Actions → 마켓 브리핑 발송 → Run workflow** 로 수동 실행해 본다.
텔레그램에 본문과 차트가 오면 끝이다. 이후 매 영업일 자동 발송된다.

## 실행 시각

`.github/workflows/daily-brief.yml` 의 cron 은 **UTC** 기준이다.

```
40 21 * * 0-4     →  06:40 KST, 한국시간 월~금
```

GitHub Actions 는 부하에 따라 수 분 늦게 시작될 수 있어 7시보다 20분 앞에 두었다.
시간을 바꾸려면 `KST − 9시간 = UTC` 로 계산하면 된다. 요일도 UTC 기준이라
한국시간 월~금은 UTC 일~목(`0-4`) 이다.

## 로컬에서 확인하기

발송 없이 본문과 차트만 만들어 본다.

```bash
pip install -r requirements.txt
SSL_VERIFY=0 python main.py --dry-run --outdir out
```

`SSL_VERIFY=0` 은 **사내 SSL 검사 프록시** 뒤에서 개발할 때만 쓴다.
GitHub Actions 에서는 붙이지 않으므로 인증서가 정상 검증된다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `sources.py` | 데이터 수집. 항목별로 독립 실패 처리(하나 실패해도 나머지는 발송) |
| `render.py` | 차트 생성. 한글 폰트는 맑은 고딕/나눔 자동 탐색 |
| `notify.py` | 본문 조립 + 텔레그램 발송(앨범 10장 단위) |
| `main.py` | 오케스트레이션 |
| `.github/workflows/daily-brief.yml` | 스케줄 실행 |

수집이 일부 실패하면 그 항목만 빠지고, 본문 하단에 `⚠️ 일부 항목 수집 실패` 로
어떤 항목이 왜 실패했는지 함께 온다. 조용히 빈 값이 나가지 않게 하기 위함이다.
